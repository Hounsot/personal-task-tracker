# Yandex AI Studio: настройка ассистента

## Что реализовано

Список и карточка задачи открывают диалог. Каждая команда независима (история не передаётся). Сервер читает до 100 последних задач текущего пользователя через его JWT и RLS, вызывает Yandex AI Studio и проверяет предложенные параметры. Сервер не выполняет изменения: клиент показывает предложение и применяет его после подтверждения с теми же правами пользователя.

Создание использует постоянный ID предложения для повторной отправки после сетевой ошибки. Изменение доступно для названия, описания, проекта, приоритета и срока. Удаление требует отдельного нажатия. Одновременные изменения с разных устройств пока используют правило последней записи.

## Шаги запуска

1. Выполните в SQL Editor Supabase файл `supabase/migrations/202609140002_task_edit.sql`. Он разрешает редактирование полей с сохранением существующих RLS-политик.
2. В Yandex AI Studio создайте/выберите каталог с подключённой оплатой, сервисный аккаунт с доступом к текстовым моделям и API-ключ. Выберите модель с поддержкой function calling. Скопируйте её полный URI из примера API. Документация: https://aistudio.yandex.ru/en/docs/ai-studio/operations/generation/completions-function
3. В Supabase → Edge Functions → Secrets добавьте `YANDEX_API_KEY`, `YANDEX_MODEL_URI` и `AI_ALLOWED_USER_IDS`. Последнее — UUID разрешённых пользователей через запятую (Authentication → Users → User UID). Отсутствие списка закрывает доступ; это ограничивает платные вызовы аккаунтами учебного теста. Для открытого запуска дополнительно нужен постоянный серверный лимит запросов/бюджета.
4. Создайте Edge Function `task-assistant` из файла `supabase/functions/task-assistant/index.ts` через редактор Supabase. Выключите проверку legacy JWT на шлюзе этой функции, если она включена: функция сама проверяет пользовательский токен через `auth.getUser()` до чтения задач и вызова Яндекса. Публичный ключ не является JWT.
5. Альтернатива редактору после авторизации CLI: `supabase functions deploy task-assistant --project-ref bvjffchnozefelfbfbry --no-verify-jwt`.
6. Откройте приложение под разрешённым аккаунтом и отправьте «Добавь задачу: проверить ассистента». До подтверждения запись не должна появляться. После подтверждения она должна переживать перезагрузку. Затем проверьте изменение, отмену удаления и подтверждённое удаление.

## Проверки перед открытым доступом

- Другой аккаунт не получает чужие задачи; произвольные ID не принимаются сервером.
- Запрос без входа получает 401; аккаунт вне списка — 403.
- При ошибке провайдера нет сообщения об успешном выполнении.
- Ключ Яндекса хранится только в Edge Function Secrets, не в VITE-переменных или GitHub.
- Для production добавить распределённые лимиты запросов, журнал действий и контроль конкурентного редактирования.

## Статус

Frontend проходит TypeScript/Vite build. Edge Function подготовлена, но не развёрнута и не проверена с реальным провайдером: нужны секреты и административный доступ в Supabase. Текущая база Supabase размещена вне РФ; подключение российского ИИ не меняет размещение базы и серверной функции.
