# Подключение Supabase Cloud

1. Создайте проект в https://supabase.com/dashboard (Free, если доступен). Пароль базы храните у себя.
2. В SQL Editor выполните весь файл `supabase/migrations/202609140001_tasks.sql` один раз. Он создаёт таблицу и правила: пользователь может читать и изменять только собственные задачи. Анонимный доступ запрещён.
3. В Authentication → URL Configuration укажите Site URL `https://hounsot.github.io/personal-task-tracker/`. Добавьте этот адрес и `http://localhost:5174/` в Redirect URLs.
4. Для самостоятельной регистрации включите Email provider. Подтверждение почты оставьте включённым. Для публичной регистрации настройте собственный SMTP: встроенная отправка Supabase имеет ограничения. Для закрытого теста можно создать подтверждённого пользователя через Authentication → Users.
5. В `.env.local` задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` по образцу `.env.example`. Используйте только publishable/anon key, никогда secret/service_role.
6. В GitHub → Settings → Secrets and variables → Actions → Variables добавьте те же две переменные. Они встраиваются в публичный клиент; доступ к данным защищён RLS.
7. Перезапустите Vite локально. Для Pages запустите workflow после отправки кода.

## Проверка перед публикацией

- Войти одним аккаунтом в двух браузерах/на двух устройствах.
- Создать задачу, обновить страницу: задача остаётся.
- Во втором браузере задача появляется при возврате фокуса или в течение 15 секунд на активной странице.
- Завершить и удалить задачу; проверить результат во втором браузере.
- Во втором аккаунте задачи первого не видны. Проверить также прямой запрос update/delete по ID чужой задачи: чужая запись не меняется.
- При отключённой сети форма сохраняет введённый текст и показывает ошибку. Повтор отправки той же формы использует прежний ID, чтобы избежать дубликата после потерянного ответа.

## Архитектура

React на GitHub Pages → Supabase Auth и Data API → PostgreSQL с RLS.
Дата срока хранится в UTC и показывается в часовом поясе устройства. Новые аккаунты получают пустой список. Моки не загружаются. Задачи не кэшируются в localStorage; сессию сохраняет Supabase SDK.
Синхронизация — опрос раз в 15 секунд и обновление при возвращении в окно. При одновременном изменении статуса действует последняя успешная запись.
Fastify/Prisma/Docker из предыдущей заготовки не используются этим вариантом. Данные облака находятся за пределами РФ; это выбранный учебный этап.
