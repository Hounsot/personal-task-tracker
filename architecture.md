# Personal Task Tracker — Architecture

## ИИ-ассистент

Выбран Yandex AI Studio. UI: `src/Assistant.tsx`; серверный адаптер: `supabase/functions/task-assistant/index.ts`. Модель предлагает одно действие, пользователь подтверждает, приложение применяет его через Supabase с RLS. Публичный запуск требует отдельного развёртывания функции и секретов; инструкция и ограничения в `AI_SETUP.md`.

## Актуальное решение — Supabase Cloud

Выбран Supabase Cloud вместо самостоятельного API: Auth, PostgreSQL и Data API с RLS. Реализация подключения находится в `src/api.ts`, вход — в `src/Auth.tsx`, SQL — в `supabase/migrations/`. Инструкция и проверка — `SUPABASE.md`. Для доступа с разных устройств используется один аккаунт. Задачи перечитываются каждые 15 секунд в активном окне и при возвращении фокуса. Создание и изменение подтверждаются сервером. Развёртывание и проверка реального облака ещё требуют создания проекта и его публичных параметров. Ниже сохранён первоначальный план; положения о моках и Fastify описывают предыдущий этап.

## Цель продукта

Focus — простой личный трекер задач для демонстрации студентам возможностей ИИ-агентов. Первый релиз — интерактивный UI без аккаунтов, сервера и базы данных.

## Пользователь и главный сценарий

Пользователь открывает список задач, создаёт новую через нижнюю форму, видит её в деталях, затем завершает или удаляет её.

## Этапы развития

1. Локальный интерактивный интерфейс (текущий этап).
2. Git/GitHub и проверка на разных устройствах.
3. Fastify API и PostgreSQL в российском облаке.
4. ИИ-функция через изолированный API-адаптер.
5. Публикация, домен, мониторинг и аналитика.

## Технологический стек

- Frontend: React, TypeScript, Vite, CSS и Lucide.
- Backend позже: Node.js, Fastify, TypeScript.
- База позже: PostgreSQL + Prisma.
- Хостинг позже: Timeweb Cloud App Platform и Managed PostgreSQL; резервно — российский VPS с Docker.

## Архитектурная схема

```text
Браузер → React-интерфейс → (позже) Fastify API → PostgreSQL в РФ
```

Сейчас задачи находятся только в состоянии React и сбрасываются при перезагрузке страницы.

## Модель данных Task

- `id`, `title`, `description?`, `project`, `dueDate?`, `priority`, `status`, `createdAt`.

## Экраны и UI-компоненты

- Splash, список задач, детали задачи, нижняя форма создания.
- `TaskRow`, `TaskSection`, `TaskDetails`, `TaskSheet`, базовые кнопки, поля и toast-уведомления.

## Границы текущего этапа

Есть локальная интерактивность. Нет авторизации, базы данных, синхронизации между устройствами, редактирования, фильтров, поиска, уведомлений, платежей, аналитики и ИИ.

## Правила хранения данных и РФ

До появления пользователей персональные данные не хранятся. При добавлении аккаунтов база и API разворачиваются у российского провайдера; отдельно проектируются согласия и политика обработки персональных данных.

## Будущие интеграции: GitHub, БД, ИИ, аналитика

- GitHub — хранение исходного кода и автодеплой.
- PostgreSQL — постоянное хранение задач.
- ИИ — только через отдельный серверный адаптер, позволяющий менять поставщика.
- Аналитика — после публикации и настройки согласия пользователя.

## Решения и принятые допущения

- MVP демонстрационный и однопользовательский.
- От 700 CSS px используется desktop-компоновка на всё окно без рамки устройства: верхняя панель с созданием задачи, список слева, детали справа, форма по центру окна. Между 700 и 1050px отступы компактнее, чтобы интерфейс работал и в узкой панели браузера. До 700px сохраняются мобильные переходы и нижняя форма; рабочая область также занимает всё окно. Цвета действий и расположение кнопок завершения и удаления сохраняются из Figma.
- Данные в демо не сохраняются после обновления страницы.
